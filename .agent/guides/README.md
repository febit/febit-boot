# 指南编写规范

> 指南只记载 **稳定之物**；实现细节、现状、进度另有所属。
> 本文件是「指南如何写」的元规范；各指南的 **内容**规范见其自身。

## 分类

| 类别     | 位置             | 内容                              | 示例                                             |
|----------|------------------|-----------------------------------|--------------------------------------------------|
| 概念指南 | `guides/`        | 设计原则、编码约定、架构规则      | `coding-java.md`、`reliability.md`、`testing.md` |
| Skill    | `skills/<name>/` | 第三方工具 / 框架的用法约定与参考 | `skills/lombok/`                                 |

判据是「这条内容 **会被违反吗**」：

- 会（不遵守就写错代码）→ **指南**（被强制的约定）。例：「`IResponse` 必须用位置占位符」。
- 不会，只是「不知道」→ **skill**（用法参考 / 操作手册）。例：「`JacksonUtils` 有哪些方法」。

同一主题的用法放在同一个 skill 内分两层（常用用法 / 详尽参考），不按「高频 / 低频」拆到两处。
路由见 `AGENTS.md` 的「按需加载」（唯一权威）。

## 通用结构

```
> 一句话描述（必须，放在标题下的 blockquote）

[正文：阐述什么 / 性质要求 / 禁令，参考结构只作示例]
[按需：## 项目附加条款]
```

> 「项目附加条款」按需：仅当存在项目特有约束时才设；无项目特征不设。

### 正文规则

- 只写 **稳定之物**：会因一次提交而失效的内容（类名清单、现状快照、进度）不进指南，归代码。
- 结构与 documentation.md 同构：阐述什么 / 性质要求 / 禁令；参考结构只作示例，不为性质单设节。
- 标题不含项目名。
- 领域概念去特征化：正文用通用术语；本仓特有概念只在「项目附加条款」映射。
- 框架 / 三方 API 不去特征：`IResponse`、`@Slf4j`、`JUnit 5` 直接用原名。
- 代码示例引用本仓实体时用通用名（`TaskId`、`store.update()`）。
- 每条禁止项只在 **一份指南**中定义，其他文件只交叉引用。
- 每份指南回答 **一个问题**（代码怎么写 / 如何保证可靠 / 如何组织测试）。

### 元信息：归属声明

> 规范正文只写「是什么 / 要求 / 禁令」；归属声明限一句话，不单设节、不带论证。

**形态**——回答「X 归哪里、本文不写什么」：

```
正确 > 红线见 coding-java.md；本文件只写用法
正确 > 完整代码范式见 references/…，此处不重复代码
错误 > 考虑到本文件定位…一方面…（论证归 doc/design/）
```

位置：约束 **整个文件**时放文件头 blockquote；约束 **单个对象**时紧邻该对象。

准入判据：

| 判据             | 说明                                      |
|------------------|-------------------------------------------|
| 改变行为         | 删掉它，Agent 会做出不同决定吗？不会 → 删 |
| 一句话可尽       | 超过一句即论证，归 `doc/design/`          |
| 附着所约束的对象 | 放文件头或被约束对象旁，不独立成节        |

### 项目附加条款

- 以 `## 项目附加条款` 作为分隔标题。
- 把通用领域概念映射到本仓实现：

  ```
  通用：原子状态转换   →  本仓：乐观锁 CAS（版本号校验）
  ```

- 框架 API 不需映射表（正文已用原名）。
- 列出该指南覆盖范围内的本仓专属禁令、配置值、框架出处。
- 引用 skill 用相对链接，例：`[febit skill](../skills/lombok/SKILL.md)`。

## 跨文件约束

| 规则     | 说明                                                                                           |
|----------|------------------------------------------------------------------------------------------------|
| 交叉引用 | 只用相对链接，不重述规则；引用 skill 形如 `[febit skill](../skills/lombok/SKILL.md)`           |
| 索引同步 | 新增 / 改名 / 删除指南后，同步更新 `AGENTS.md` 规范表与 `.agent/README.md`，并同步受影响的链接 |
| 冲突裁决 | 工具强制（lint / editorconfig）> 指南约定 > 个人偏好；P0 优先于 P1，同优先级以主题更具体者为准 |

## 格式要求

- 标题层级：`#` 文件标题 → `##` 大节 → `###` 小节。
- 标题下必须有 `>` blockquote 概述。
- **`>` 只用于两处**：文件头一句话描述（不超过 2 行），或紧邻被约束对象的一句归属声明。
  其余（多句说明、并列多条、含列表或表格）写成普通段落、列表或表格；`>` 内不嵌套列表与表格。
- **行宽**：正文 / 列表 / 引用单行显示宽度不超过 120（中文按 2 计）；长句换行，不在一行堆叠多句。
  frontmatter 的 `description` 与含长链接的表格行不受此限（以渲染宽度为准）。
- **表格**：单元格只放短语（链接名 / 关键词），不塞整句解释——
  单元格放不下就改用列表（列表可换行，表格不能）；表宽不超过 4 列。
- **强调**：`**粗体**` 只标关键术语与禁令，不逐句加粗。
- 表格优先于段落：配置、对照、级别等一律用表格。
- 正反例并列：`// 正确` 与 `// 错误` 成对出现。
- 代码块标注语言（```java）。
- 表格分隔符用 `|:--|` 左对齐、`|:--:|` 居中。
- 禁止：分段注释（`// ---`）、装饰性 emoji、正反例用 emoji 标记（改用「正确 / 错误」文字）。
- 指南文档用中文叙述。

## 命名

- 概念指南：名词，小写英文，`-` 分隔（`coding-java.md`、`reliability.md`、`code-comment.md`），不带 `tool-` 前缀。
- Skill：目录 `skills/<name>/`，按所属工具 / 框架命名（`febit`、`lombok`），不按用途命名。

> 写完对照本文各节自查；不另设复述式检查清单。
