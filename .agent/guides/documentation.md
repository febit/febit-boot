# 文档编写规范

> 文档只记载 **稳定之物**；易腐内容另有归属。

## 设计原则

- **只记稳定之物**：会因一次提交失效的（类名 / 现状 / 进度）归代码，不进文档。
- **分流不禁止**：易腐内容各有归属，只禁止记在文档里。
- **性质不降格为章节**：稳定 / 边界 / 可验证性是全篇性质，用性质要求约束每条陈述，不单设节。
- **就近**：决策理由写在结论旁、规则写在所约束对象下、异常打散进所属场景的验收标准，不收进集中清单；
  规范类文档（guides / skills）不写理由，设计文档（design）的取舍写在结论旁。
- **判据优先于清单**：给可迁移的判据（一次提交会失效吗、谁能引起变更、用户观测得到吗），不给穷举清单。

## 防腐严律

| 易腐化内容                                    | 该去哪                               |
|-----------------------------------------------|--------------------------------------|
| 实现细节（类名 / 方法 / 表 / SQL / key 路径） | 代码本身                             |
| 进度（已建 / 待建 / 部分实现）                | 不记载，由代码回答                   |
| 现状快照（有哪些模块 / 配置）                 | 代码 / 运行时                        |
| 妥协、已知限制、待修缺陷                      | 设计固有代价写结论旁，其余由代码回答 |
| 决策推敲过程（选 A 舍 B 的来回）              | 不另立文档，取舍写在设计结论旁       |
| 历史演进 / 版本变化                           | git 历史                             |

文档头不标状态（「已完成 / 部分实现 / 未实现」）；能力是否具备，看代码。

## 类型与职责

**设计**（`doc/design/`）——只阐述三件事：它是什么（领域概念 / 聚合）、它怎么变（状态流转 / 生命周期）、
为什么这样（取舍，写在结论旁）。
不记：实现与配置值、进度与状态头、实现清单。
「边界 / 稳定 / 契约 / 可验证性」是全篇性质，不单设节。

**索引**（各目录 `README.md`）——导航：这组文档答什么、哪篇答哪块。不记：语义复述、状态、进度。

## 归属

- 概念只在 **归属它的那一篇**定义完整语义。判据： **谁的变更会引起它变更**。
- 跨模块共享的枚举 / 类型归属 **代码**（写清类名），文档只引用。
- 动笔前 grep 概念名（范围 `doc/` + `.agent/`）；命中他处定义 → 只给一句用途 + 链接，不重写。

## 收口前

跨引用只到 **文档**一级：Markdown 链接只指向文档本身，不加章节锚点、不写章节编号。

改完自检链接是否失效：改文件名 / 移目录后断链。

索引表中的每一项必须是可跳转链接，不能写反引号纯文本。

> 其余自查项即本文各节，不另设复述清单。
