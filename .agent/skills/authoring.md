# Skill 编写规范

> 新增或重构 skill 时读。 **使用 skill 不必读本文件**——
> 清单见 [README.md](README.md)，路由见 [AGENTS.md](../../AGENTS.md)「按需加载」。

## 结构（对齐 Agent Skills 开放规范）

```
skills/<name>/
├── SKILL.md              # 必需：一级加载，含 YAML frontmatter + 使用约定
└── references/           # 可选：二级按需加载的补充文档
    └── *.md
```

| 要求        | 规定                                  |
|-------------|---------------------------------------|
| 文件名      | `SKILL.md`（不是 `prompt.md`）        |
| frontmatter | 必需：`name` + `description`          |
| 主文件规模  | 建议 < 500 行；超出则拆 `references/` |
| 可选目录    | `scripts/`、`references/`、`assets/`  |

### 渐进式披露

|  级别  | 加载时机                     | 内容                                  |
|:------:|------------------------------|---------------------------------------|
| 元数据 | 启动即加载（~100 tokens/个） | frontmatter 的 `name` + `description` |
|  指令  | Skill 激活时                 | `SKILL.md` 正文                       |
|  资源  | 按需                         | `references/` 等                      |

> `description` 必须写清用途与不适用场景，不能是一句泛泛标题。

### 主文件与 references 的分工

- `SKILL.md`：写 **约定**——不遵守会写错代码的内容，及指向 references 的导航。
- `references/`：写 **参考 / 操作**——不查就不知道、但不会「违反」的内容；按触发时机拆分。

判定：这条内容会被「违反」吗？会 → `SKILL.md`；不会，只是「不知道」→ `references/`。

### 分类与命名

目录按 **所属工具 / 框架**命名（`febit`、`lombok`），不按用途命名。
分类：`java/` / `testing/`（顶层）/ `clean-code/`（顶层，唯一方法论类）。

> skill 只装 **可复用能力**的用法，不装本仓业务领域知识；判据：换到同类项目是否仍成立。
> 本仓业务实体的模型与端点清单属代码事实，设计取舍归 `doc/design/`。

## 内容三维度

| 维度     | 回答                                   | 形态                   | 何时写                            |
|----------|----------------------------------------|------------------------|-----------------------------------|
| 用法     | 这个能力怎么调用                       | 速查表 + 正反例        | 必有                              |
| 扩展触发 | 什么时候该新增一个抽象，而非就地硬编码 | 触发条件表，含反向条目 | 该 skill 覆盖的基建可被扩展时必写 |
| 范式扩展 | 新增功能时跨层逐层该加什么             | 纵向切片清单           | 不在 skill 内写                   |

- **扩展触发必须双向**：每条正向触发都要配一条「何时不要」。
- **范式扩展不落 skill**：跨层铺开的功能扩展手册归 `.agent/guides/` 或 `doc/`；skill 只覆盖自己那层。

判定自己属于哪一维：

| 问题                   | 归属     |
|------------------------|----------|
| 不知道怎么调           | 用法     |
| 不知道该不该新建一个   | 扩展触发 |
| 不知道功能该铺在哪几层 | 范式扩展 |

## 红线

- 只写用法不写扩展触发——该基建可被扩展时必写扩展触发。
- 扩展触发只有正向条目——缺反向即诱导过度设计。
- 在 guides 已定义过的禁止项，skill 不重复——只单向链接。
- `references/` 复述 `SKILL.md` 已有的红线声明。
- 在 `SKILL.md` 放完整代码块（归 `references/`，入口只给判据与步骤）。
- `description` 写成泛泛标题，不写清何时用 / 何时不用。
- 引用 design 文档只为了解「设计意图」——若 design 有 skill 缺的操作性内容，先搬内容再删引用。
- 归属声明单设节或展开论证——限一句话，放文件头或紧邻被约束对象（详见 [guides/README.md](../guides/README.md)）。
- 写使用次数 / 存量统计 / 落地情况这类易漂移且无关的元数据（`（0 处）`、`全仓 grep 零使用`、
  `当前无调用点`、`X 与 Y 并存是正常形态`、`曾是别名已废弃` 等）——随代码与依赖版本变动即失真。
  要说明某注解 / 模式「基本不用 / 是例外」，直接给规范约束（禁止 / 慎用 + 何时例外），
  不列计数、不叙述迁移 / 共存 / 历史状态。标记废弃 API 并指向替代属禁令范式，可保留。
